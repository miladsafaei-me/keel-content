## P1 — Next up
- [ ] **The pre-clean's inline-HTML emphasis makes a line unlinkable.** `html_to_markdown.preclean` emits `<strong>x (</strong>` as raw inline HTML where the `**` form would not parse (v0.10.0), and `internal_links._is_prose_line` rejects any line carrying an HTML tag — so those paragraphs silently drop out of the linkable surface. Correct in isolation on both sides: the emphasis has no Markdown spelling, and a tag-bearing line really is unsafe to insert into blind. But the interaction shrinks what a linking pass can reach, and nothing reports it. Two candidate fixes: teach `_is_prose_line` to allow a closed inline-formatting tag (`strong`/`em`/`b`/`i`) while still rejecting block/visual markup, or have the pre-clean prefer a Unicode-safe Markdown spelling before falling back to HTML. Measure the affected share first — on the corpus that motivated the pre-clean it was small.
- [ ] **A linking pass cannot see anchors already claimed elsewhere on the site.** `content_relink --scope cluster` deliberately never touches the anchor registry (only `cross-cluster` does), so a within-cluster pass can hand an anchor to a target that another cluster already claims. Measured 2026-08-23 on Sarmayeh: a 271-edge pass produced 9 site-wide conflicts, 7 of which were adjudicated and repointed afterwards. Making the default scope consult the registry read-only — reject a claimed anchor, report it, propose nothing — would prevent them instead of cleaning up after. The reason it does not today is that the default scope's behaviour is pinned byte-identical to its pre-`--scope` self; changing that is a deliberate break worth its own decision.
- [ ] **A too-generic anchor has no right target, and the verdict format cannot say so.** `anchor_registry_apply` takes one winner per anchor and repoints every other link to it. Two of Sarmayeh's nine conflicts had no correct winner: "عبارت بازیابی" (recovery phrase) is claimed by three wallet-specific recovery articles, and "حداقل سرمایه" (minimum capital) by a forex one and a stock-market one — in each case every existing link is already contextually right, and repointing them would make the corpus worse. They were held out of the run by hand. The registry needs a third verdict besides winner/loser — something like `"resolution": "disambiguate"` — that reports the anchor as needing a more specific phrase in each source rather than a single owner, so the decision survives in the file instead of in a human's head.
- [ ] **47 Sarmayeh Media articles still have no Markdown body, and the reason is Markdown itself.** `backfill_markdown_source` now converts 1,043 of 1,090 (95%) — the pre-clean landed 2026-08-23 and took the unconverted set from 322 to 47. What is left is not editor noise: 23 of them nest a `<ul>` inside a `<td>` or inside another list item, 5 put an `<h3>` inside an `<li>`, and one stores its whole body inside a ```html fence. Markdown cannot express any of those, so the gate is right to refuse them and no amount of pre-cleaning will move them. Two real options, neither chosen: (a) an HTML-aware link inserter in `core/internal_links.py` so an HTML-bodied post can still receive internal links, or (b) a content pass that simplifies those 47 articles' structure (flatten the nested lists) so they convert like the rest. Until one is picked they stay invisible to every Markdown pass; `content_relink export --skip-empty-bodies` is how the other 95% gets linked meanwhile.
- [ ] **The glossary AUTHORING/PERSISTING commands still assume keel-cms's Tag shape.** `author_glossary_terms` and `persist_glossary_terms` write `is_term=True` and read `.name` directly, and `persist_glossary_terms`'s emitted migration hardcodes `Tag.objects.filter(is_term=True)`. - [ ] **`keel_cms.Post` implements no `get_absolute_url`, so every keel-cms host MUST wire `KEEL_CONTENT["post_url_hook"]`.** `keel_cms.Tag` has one (it reverses `keel_cms:trading_glossary_term` / `keel_cms:tag_detail`); `Post` has none at all, so keel-content's fallback chain has nothing to fall back on and `host.post_url` returns `""` — which now correctly refuses rather than guessing, but means the hook is mandatory rather than optional for Binary, Martiland, Sarmayeh and Prop.
